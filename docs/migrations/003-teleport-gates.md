# 003：传送门与地图切换迁移

## 状态

已完成。

## 目标

把 C# `TeleportGates` 数据、客户端进入传送门请求和服务端地图切换响应迁移到 Go，并确保地图切换是 `gameworld.World` Actor 中的原子操作。

## 数据兼容

Go 服务启动时从以下旧数据库目录加载数据：

```text
Database/System/GameMap/TeleportGates/*.txt
Database/System/GameMap/Maps/*.txt
Database/System/GameMap/Terrains/*.terrain
```

支持原 JSON 字段：

- `TeleportGateNumber`
- `TeleportGateName`
- `FromMapId` / `ToMapId`
- `FromCoords` / `ToCoords`
- 目标地图 `MinLevel`

加载阶段会拒绝重复的 `(FromMapId, TeleportGateNumber)`、不存在的源/目标地图、非法编号和非法坐标。仓库当前的 555 个传送门定义可直接加载。

## 协议兼容

### 客户端

- `22`：进入传送门，固定 6 字节，传送门编号位于偏移 `2`。

### 服务端

- `9`：游戏错误消息。
- `40`：离开当前场景。
- `41`：切换地图，保留 C# 的字段偏移和协议坐标转换。
- 同地图传送继续使用 `48`（停止）、`39`（进入场景）、`60/62/64/78`（AOI 对象同步）。

错误码与 C# 保持一致：

| 场景 | 错误码 |
| --- | ---: |
| 传送门或目标地图不存在 | 775 |
| 距传送门大于等于 8 格 | 4609 |
| 等级低于目标地图要求 | 4624 |
| 目标地图已满或落点不可用 | 769 |

## 世界状态规则

1. 只允许处于 `PlayingScene` 的已激活玩家请求传送。
2. 服务器使用权威位置计算 Chebyshev 距离，不信任客户端坐标。
3. 在 Actor 内完成传送门查找、距离校验、等级校验、地图容量校验和落点占用校验。
4. 目标点被占用或阻塞时，在目标点三格内按确定顺序寻找最近可用格；找不到则拒绝，原状态不变。
5. 跨地图传送会从旧地图及占位表移除玩家，将玩家加入新地图的未激活集合，等待客户端场景加载完成后再激活 AOI。
6. 同地图传送立即重建旧、新 AOI，向双方发送对象消失和重新出现消息。
7. 成功传送后立即持久化地图、坐标、方向、HP 和 MP；断线时仍会再次保存最终状态。

## 测试

新增或扩展的测试覆盖：

- 测试夹具中的传送门 JSON 加载和索引。
- 仓库真实系统数据库中的传送门兼容性。
- 跨地图传送、旧地图 AOI 清理和目标地图延迟激活。
- 同地图传送及新旧 AOI 重建。
- 不存在的传送门、距离过远和最低等级拒绝。
- 失败传送不修改玩家状态。
- 地图切换包与错误包的 ID、长度、字段偏移和坐标编码。

验证命令：

```bash
go test -race ./...
go vet ./...
go build ./cmd/accountserver ./cmd/gameserver
```
