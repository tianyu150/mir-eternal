# 004：静态守卫/NPC 与 AOI 迁移

## 状态

已完成静态守卫的加载、场景可见性、阻挡和基础外观数据请求。NPC 对话、商店和战斗 AI 不在本任务范围内。

## 目标

把 C# `Guards` 模板、`MapGuards` 地图放置数据及其客户端可见协议迁移到 Go，使玩家进入场景或移动时能够看到旧系统数据库中的静态守卫/NPC，并由世界 Actor 维护其碰撞和可见性。

## 数据兼容

加载以下旧数据库目录：

```text
Database/System/Npc/Guards/*.txt
Database/System/GameMap/Guards/*.txt
```

支持的模板字段：

- `Name`
- `GuardNumber`
- `Level`
- `Nothingness`

支持的地图放置字段：

- `GuardNumber`
- `FromMapId`
- `FromCoords`
- `Direction`

兼容处理包括：

- UTF-8 BOM；
- 旧文件中的非 UTF-8 名称字节，`encoding/json` 按替换字符处理，但不影响协议模板编号；
- 四个旧 `MapGuards` 文件中 Newtonsoft 可接受的尾随逗号；
- 缺省方向按 C# 枚举的 `左方 = 0` 处理；
- 八个中文方向名称按 `0..7168`、步长 `1024` 转换。

加载时会拒绝重复模板、未定义模板、未定义地图、非法坐标和未知方向。仓库现有 66 个守卫模板与 189 个地图放置定义均通过兼容测试。

## 对象标识与世界状态

- 静态守卫使用从 `1,500,000,001` 开始的稳定正整数对象 ID，避免与当前角色 ID 范围冲突。
- 文件按名称排序后分配 ID，同一数据库版本重启后保持稳定。
- C# `GuardObject` 的默认最大 HP `9999` 被保留。
- `Nothingness = false` 的守卫注册到地图占位表，会阻止玩家走入对应格子。
- `Nothingness = true` 的守卫可见但不阻挡移动。
- 守卫高度从旧 `.terrain` 单元计算，不信任地图放置文件提供高度。
- 静态守卫不进入动态处理循环，不产生不必要的 goroutine。

## AOI 行为

以下世界事件会计算静态守卫可见性：

1. 玩家首次进入场景；
2. 玩家走路或跑步进入/离开守卫视野；
3. 同地图传送重建视野；
4. 跨地图传送后在目标场景重新激活。

玩家离开守卫视野时发送对象消失包。守卫本身是静态对象，因此不需要接收玩家 AOI 广播。

## 协议兼容

### 客户端

- `19` `RequestObjectDataPacket`：请求对象基础数据。

请求只允许查询与玩家同地图且处于当前 AOI 范围内的守卫，避免通过任意对象 ID 探测其他地图。

### 服务端

守卫进入视野时发送：

- `48`：对象停止和坐标；
- `60`：对象进入视野；
- `78`：对象 HP。

客户端请求对象数据后发送：

- `65` `SyncNPCData`：对象 ID、`GuardNumber`、等级、质量 `3` 和最大 HP。

不存在或不可见的对象返回：

- `514`：社交错误 `6732`，与 C# 行为一致。

所有字段继续使用原小端序、固定长度和 `0x81` XOR 协议。

## 可观测性

GameServer `/stats` 新增：

```json
{
  "static_guards": 25
}
```

该值表示当前已加载地图实例中的静态守卫数量，而不是整个系统数据库总数。

## 测试

- 模板和地图放置加载；

- 中文方向枚举；
- 仓库真实地图 142 的 25 个守卫；
- 真实大刀守卫模板、坐标和方向；
- 场景激活时进入 AOI；
- 移动导致守卫进入/离开 AOI；
- 阻挡型守卫阻止玩家移动；
- 仅允许查询当前 AOI 中的守卫；
- `48/60/65/78` 的 ID、字段偏移、坐标、方向、模板和 HP 布局。

## 已知限制和后续任务

- NPC 点击、脚本对话、任务页面、商店和仓库接口尚未迁移。
- 可受伤守卫的战斗、仇恨、技能、死亡、尸体消失和复活尚未迁移。
- 动态创建的攻城守卫及竞技场随机移动守卫尚未迁移。
- 当前仅发送客户端显示所需的基础 NPC 数据，模板中的 `StoreId`、`InterfaceCode` 和技能字段保留给后续任务。
